    ScopusLit: An end-to-end Web-based tool for bibliometric analysis¶

    Orlando Arroyo

    Universidad Industrial de Santander, Bucaramanga, Santander, Colombia

    A R T I C L E I N F O¶

    Keywords: Bibliometric analysis Scopus Systematic literature review Topic modeling

    A B S T R A C T¶

    Bibliometric analysis supports systematic literature reviews, but it often requires disconnected tools for search, data storage, analysis, visualization, and export. This paper presents ScopusLit, an open-source, browser-based application for analyzing scientific literature indexed in Scopus through an integrated, zero-code workflow. Developed in Python with Streamlit and pybliometrics, ScopusLit executes Scopus Advanced Search queries through the API, retrieves abstracts, stores reproducible JSON datasets, and provides bibliometric, network, and abstract-level text analyses. Its functionality is demonstrated using a search query that retrieved 1036 records in 52 s and downloaded abstracts with 100% success in 678 s. The example illustrates temporal, geographic, keyword, co-occurrence, TF-IDF, and topic-modeling outputs, including network generation and NMF topic modeling. By combining Scopus-based retrieval, analysis, consolidation, and publication-ready export in a single web interface, ScopusLit reduces manual transfers between tools and supports reproducible bibliometric workflows for review-oriented research.

    1. Motivation and significance¶

    Bibliometric analysis is a cornerstone of systematic literature reviews, research trend identification, and science mapping [1]. Researchers frequently rely on the Scopus database, one of the largest curated abstract and citation databases of peer-reviewed literature, encompassing over 27,000 titles from >7000 publishers [2]. However, conducting rigorous bibliometric studies typically requires combining multiple disconnected tools: Scopus’s web interface for search, spreadsheet software for data cleaning, specialized bibliometric software for analysis, and graphic design tools for producing publication-quality figures.

    While several established tools facilitate these analyses, they often present distinct limitations. For instance, VOSviewer [3] excels in the network visualization of co-authorship, co-citation, and keyword co-occurrence, yet it lacks text analysis capabilities and requires manual data importation. Similarly, Bibliometrix [4] offers comprehensive bibliometric indicators but demands proficiency in R programming. Tools like CiteSpace [5] and Publish or Perish [6] also exhibit constraints, either by relying on manual file transfers or offering limited visualization and text analysis capabilities. Consequently, none of these alternatives provides an integrated, zero-code workflow that spans from Scopus query execution to abstract-level text analysis. Conversely, programmatic solutions such as the pybliometrics Python library [7] offer robust API access but requires coding expertise, limiting accessibility for non-programmers.

    To bridge this gap, this paper introduces ScopusLit, a web-based application designed for the comprehensive bibliometric analysis of Scopus-indexed literature. Developed in Python using the Streamlit web framework [8] and the pybliometrics API client [7], ScopusLit delivers an end-to-end workflow. The tool executes Advanced Search queries, persists results locally, generates over 20 types of bibliometric visualizations, performs natural language processing on abstracts, and exports publication-ready datasets and figures. It is specifically designed to support researchers, graduate students, and authors who require a streamlined process for producing review articles and comparing multiple search strategies.

    ScopusLit has three distinctive features. First, it consolidates search execution, full abstract retrieval, and analysis into a single environment, eliminating manual file transfers. Second, it natively integrates advanced text analytics—specifically TF-IDF extraction and topic modeling (NMF/LDA) on abstracts. Third, its consolidation feature enables union and comparison modes via Venn overlap analysis, directly supporting the multi-query workflows essential to the PRISMA systematic review methodology [9].

    2. Software description¶

    2.1. Software architecture¶

    ScopusLit is implemented as a single Python file (app.py) organized into 10 sections. The application follows a functional programming paradigm with grouped utility functions comprising 74 functions in total. While this design favors portability and ease of inspection, the functional nature is friendly to modularization to improve maintainability and scalability. Running the main script starts a local Streamlit web server accessible from any browser.

    The application follows a three-layer separation. The data layer (Sections 2–4 of the source code) handles all interactions with external systems, including Scopus API communication via pybliometrics for searches and abstract retrieval, and local file system operations for JSON persistence. All API calls are wrapped in retry logic to respect Scopus rate limits. The analysis layer (Section 5-6 of the source code) contains pure computation functions that take pandas DataFrames or abstract dictionaries as input and return processed data structures. These functions have no side effects and no dependency on Streamlit, making them independently testable. Section 5 covers bibliometric computations (publication counts, author rankings, citation statistics, and cooccurrence network analysis), while Section 6 covers natural language processing (TF-IDF vectorization, topic modeling, word cloud generation). The presentation layer (Sections 7–9 of the source code) handles all visualization using Plotly [10] and matplotlib [11], data export via openpyxl [12] and pandas, and user interface rendering through Streamlit components, session state, and page routing.

    ScopusLit uses Streamlit’s session state mechanism to persist appli cation state across user interactions, since Streamlit re-executes the entire script on every widget interaction. Eleven state variables manage the currently loaded search, cached DataFrames, h-index data, topic modeling results, and navigation state. Loading a search populates the search data and its derived DataFrame; loading a consolidation populates the merged DataFrame and combined abstracts. Each search is stored as a self-contained JSON file with a UUID-based filename in a local data directory, capturing the query string, execution date, complete result set, and any downloaded abstracts.

    2.2. Software functionalities¶

    ScopusLit implements 20 features organized into five functional categories: search and storage, bibliometric analysis, abstract text analysis, search consolidation, and export.

    • Search and Storage. Users initiate the workflow Fig. 1 by entering a Scopus Advanced Search query. To conserve API quotas, ScopusLit features a "Result Estimation" function that retrieves the expected document count before initiating a full download. Once executed, the search results—including all metadata—are saved automatically. Users can subsequently trigger the abstract download module, which retrieves full abstract texts incrementally, saving progress every 25 documents to prevent data loss during long retrieval processes or network interruptions.

    • Bibliometric Analysis. Upon loading a saved search, a tabbed interface provides comprehensive, interactive visualizations of the dataset. Key analyses include:

    ○ Timeline and Sources: A dual-axis chart displays publications per year alongside cumulative growth, while a horizontal bar chart identifies the top 15 publishing journals. ScopusLit citation analysis is implemented through the Scopus citedby_count field. The software computes total citations, mean citations, median citations, and maximum citations for the retrieved corpus. It also identifies the top 20 most cited documents, generates a citation distribution histogram, and plots average citations by publication year. The software groups publications by year, calculates cumulative publication counts, identifies the peak publication year, and visualizes annual production trends.

    ○ Geography and Authorship: Geographic distribution is mapped using an interactive choropleth world map, alongside top contributing countries and affiliations. The author tab highlights top contributors and features an on-demand "Fetch h-index" tool that queries the AuthorRetrieval API. Co-authorship and collaboration patterns are addressed through both tabular and networkbased analyses. The software extracts author names from Scopus metadata, counts the most productive authors, identifies frequent

In addition, it builds co-occurrence networks using networkx, including author co-authorship networks, keyword cooccurrence networks, and country collaboration networks.     • Abstract Text Analysis. When abstracts are successfully retrieved, ScopusLit unlocks an advanced natural language processing (NLP) pipeline.

    The text-analysis workflow has three components. First, the abstract word cloud concatenates all non-empty abstracts and removes a combined stopword list composed of the default wordcloud English stop words, an added Spanish stopword list, and additional domain-generic terms such as “abstract,” “study,” “results,” “method,” “research,” “analysis,” “data,” “model,” “et,” and “al.”

    Second, the TF-IDF module uses scikit-learn’s TfidfVectorizer [13]. The default parameters are: max_features=1000, stop_words="english", max_df=0.85, min_df=2, and ngram_range=(1, 2). Thus, the system considers unigrams and bigrams, excludes very common terms appearing in >85% of abstracts, excludes terms appearing in fewer than two abstracts, and returns the top 30 terms ranked by average TF-IDF score across the corpus. At least three non-empty abstracts are required. Third, topic modeling is performed on TF-IDF vectors using either Non-negative Matrix Factorization or Latent Dirichlet Allocation, selected by the user in the interface. The default method is NMF, and the default number of topics is five. Users can choose between 3 and 10 topics through a slider. The topic model uses max_features=2000, stop_words="english", max_df=0.85, and min_df=2. For NMF, the software uses n_components=n_topics, random_state=42, and max_iter=300; for LDA, it uses n_components=n_topics, random_- state=42, and max_iter=20. The model requires at least max(5, n_topics) non-empty abstracts. ScopusLit provides an exploratory interface in which the user specifies the desired granularity. A lower number of topics gives broader thematic groupings, whereas a higher number gives more specific but potentially more fragmented themes. Importantly, the TF-IDF is implemented in the compute_tfidf_terms(); NMF/LDA topic modeling is implemented in compute_topic_model() .

    • Search Consolidation. To support complex systematic reviews that require the synthesis of multiple search strings, ScopusLit includes a powerful consolidation module. Researchers can select multiple saved searches and merge them in one of two modes:

    ○ Union mode: Concatenates datasets and automatically dedupli cates entries based on the Scopus unique identifier (EID), applying the full Phase 2 and 3 analytical pipeline to the merged corpus.

    ○ Comparison Mode: Generates comparative visualizations, including overlaid publication timelines, grouped keyword bar charts, and a document overlap analysis utilizing tabular statistics and Venn diagrams based on Matplotlib [14,15] (for up to three searches) to illustrate the precise intersection of different research queries.

    • Export Capabilities. The platform ensures comprehensive data portability. Full results and analytical summaries can be exported as CSV files or multi-sheet Excel workbooks. Concurrently, all charts—which adhere to a cohesive visual specification utilizing the color-blind friendly Set2 palette—can be exported as publicationready 300 DPI PNG files via the Kaleido rendering engine [16] and Matplotlib.

    User navigation is seamlessly routed through a four-page structure (New Search, Saved Searches, Analysis, Consolidation), supported by a persistent sidebar for rapid access to saved datasets.

    3. Illustrative example¶

    This example demonstrates and profiles the performance of ScopusLit using the search equation: TITLE-ABS-KEY(("learning analytics" OR "academic analytics" OR "educational data mining") AND ("at-risk student*" OR "student risk" OR "academic risk" OR "early warning" OR "early alert" OR "dropout prediction" OR "student performance prediction" OR "course failure" OR "academic failure") AND ("predictive model*" OR "risk model*" OR "machine learning" OR "classification" OR "prediction" OR "analytics dashboard*" OR "early warning system*")). The goal of this search was a broad search on analytics applications to quantify student risk, especially in learning analytics / educational data mining. A companion video demonstrating the application functionality with another search equation is also available at the link referenced in the Code Metadata Table. After inserting the equation, the results estimation was 1036 documents, whose title information was recovered in 52 s, yielding a rate of roughly 20 documents/s. Subsequently, abstract retrieval was conducted in 678 s with 100% success, for a rate of 1.5 abstracts/s. Similar timings were obtained for equations that yielded larger and smaller corpus. ScopusLit stores the results in a single JSON format for portability and allows exporting the results in either CSV or Excel files for easier inspection. The file size for this case was 4.5 MB. ScopusLit allows a variety of bibliometric analyses based on the information stored in the JSON files. Basic ones include the citation count and the country distribution, as exemplified in Figs. 2 and 3. These two figures appear instantly on their corresponding tabs once an analysis is run.

    Network analysis is another feature of ScopusLit. It performs cooccurrence networks of words, countries and authors. For this purpose, it extracts the affiliation_country, author_names and authkeywords fields from the Scopus metadata stored in the JSON files and leverages NetworkX Python library to create co-occurrence, co-authorship and Country collaboration networks. Users can define the minimum number of co-occurrences and maximum number of nodes. Fig. 4 displays the word co-occurrence network, which was generated with 6 minimum cooccurrences and 40 maximum nodes in 13.7 s on an Apple M4 Pro SoC,.

    Previous figures were generated using the entire set of search results. ScopusLit allows result generation using filtered search results. Users can filter by year range, document types, countries and minimum citations. Fig. 5 show the results for keyword analysis -word cloud and evolution along time- when a filter is applied to consider journal articles and years between 2016 and 2026.

    Based on the abstract retrieval, ScopusLit performs text analysis based on documents for which abstracts were downloaded. On the text analysis tab, the app indicated the number of abstracts available for the process. Word clouds (see Fig. 6), TF-IDF and topic analysis. For the latter, users can select either the NMF or LDA [13] techniques.(Fig. 7)

    Fig. 7 shows the topic-word heatmap over the entire search results using NMF for 5 topics, which was generated by ScopusLit in 2 s. The LDA analysis yields almost identical results in 3 s. Users interpret the output by examining the top 10 weighted terms for each topic and the accompanying topic-word heatmap. The listed terms indicate the semantic content of each latent topic, while the heatmap shows the rela tive contribution of each term to each topic. The output should be interpreted as an exploratory thematic summary of the abstract corpus.

    4. Impact¶

    Bibliometric analysis is essential for literature reviews and is argu ably among the most transversal and interdisciplinary tool researchers have at their disposal. It has been applied across disciplines such as resource allocation [17], engineering education [18] and underground mining operations [19]. ScopusLit is an open-source tool that lowers the barrier to bibliometric analysis by integrating search, analysis, and visualization into a single browser-based interface with no programming requirement. This makes quantitative literature analysis accessible to researchers who lack programming skills or familiarity with specialized bibliometric software. Table 1 compares ScopusLit with established bibliometric tools across key functional dimensions.

    Table 1 compares ScopusLit with established bibliometric tools using a functional criterion: a feature is marked as supported when it is available natively within the tool’s standard workflow, limited when it is available only for a narrower subset of outputs or with restricted customization, partial when it can be achieved through additional steps, scripts, or external packages, and not supported when it is not part of the tool’s documented workflow.

    As shown in Table 1, ScopusLit’s main contribution is the native integration of Scopus query execution, abstract retrieval, bibliometric analysis, abstract-level text mining, search consolidation, and export within a single browser-based, zero-code interface. Established tool such as VOSviewer, Bibliometrix, CiteSpace, and Publish or Perish provide mature and widely used capabilities, particularly for science mapping, citation analysis, and bibliometric indicators. However, ScopusLit emphasizes a different use case: reducing manual transfers between platforms and supporting multi-query, Scopus-centered systematic review workflows from data retrieval to publication-ready outputs.

    The tool enables reproducible bibliometric workflows. Each search is persisted as a JSON file that captures the query, execution date, full result set, and downloaded abstracts. This enables exact reproduction of analyses and facilitates sharing of bibliometric datasets between collaborators. The consolidation feature, with both union and comparison modes, directly supports the multi-query workflow typical of systematic reviews following the PRISMA methodology [9].

    The inclusion of TF-IDF term extraction and topic modeling on full abstract corpora represents a capability not available in the most widely used bibliometric tools. This allows researchers to move beyond keyword-based analysis to identify latent thematic structures in the literature, which is particularly valuable for characterizing emerging or interdisciplinary research fields. From a practical standpoint, every visualization can be exported at 300 DPI, meeting the minimum resolution requirements of most scientific journals. The multi-sheet Excel export provides immediately usable supplementary materials for review articles.

    5. Conclusions¶

    This paper presented ScopusLit, an open-source, web-based appli cation for bibliometric analysis of scientific literature indexed in the

    Scopus database. The tool is built on Python with Streamlit and pybliometrics, and provides a complete workflow from search execution through analysis and export without requiring programming knowledge from the user.

    The key contributions of ScopusLit are the integration of API-based search, abstract retrieval, and analysis within a single zero-code interface; the incorporation of TF-IDF and topic modeling on abstracts; cooccurrence network analysis for keywords, authors, and countries; and the search consolidation feature with union and comparison modes supporting systematic review workflows. An illustrative example shows that ScopusLit can retrieve, store, analyze, and visualize a corpus of more than one thousand records using a reproducible JSON-based workflow. The results demonstrate the practical value of combining API-based retrieval with bibliometric indicators, co-occurrence networks, TF-IDF extraction, and topic modeling in one environment. A full workflow of document and abstract retrieval on a query of 1036 took <15 min, including figure generation and abstract topic modeling.

    The main current limitation is the exclusive dependence on Scopus metadata and API access. As a result, ScopusLit does not yet support multi-database retrieval or advanced citation-based analyses such as cocitation and bibliographic coupling. From a software-development perspective a future direction is to transition ScopusLit from its current monolithic implementation toward a modular architecture, which would improve maintainability, facilitate testing, and encourage community-driven extensions and contributions.
