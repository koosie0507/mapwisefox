    App4WoSCCinR: a web-based bibliometric analysis platform for the web of science core collection¶

    Tsair-Wei Chien a, Lifan Chen b,*, Willy Chou c,d,**

    a Department of Medical Research, Chi Mei Medical Center, Tainan, Taiwan

    b Department of Nursing, An Nan Hospital, China Medical University, Tainan, Taiwan

    c Department of Leisure and Sports Management, CTBC University, Tainan, Taiwan

    d Department of Physical Medicine and Rehabilitation, Linyin Chi-Mei Hospital, Tainan 710, Taiwan

    A R T I C L E I N F O¶

    Keywords: Bibliometric software WoSCC metadata Visualization framework AAC metric Web-based application

    A B S T R A C T¶

    Numerous bibliometric studies rely on specialized software to visualize Web of Science Core Collection (WoSCC) metadata, but direct, reproducible workflows for standard 72-column XLS files remain limited. We developed App4WoSCCinR, a web-based framework that enables users to upload WoSCC metadata and execute bibliometric analysis through a simple two-step process. Using SoftwareX articles published between 2017 and March 2026 as an illustrative dataset, the application generated a structured performance summary and visual outputs across countries, institutions, departments, authors, journals, keywords, and temporal trends. It also incorporates the Absolute Advantage Coefficient (AAC) to identify dominant entities within bibliometric networks. The demonstration showed that App4WoSCCinR can efficiently transform standard WoSCC metadata into interpretable summaries and visual analytics for research evaluation. Overall, the framework provides a practical and transparent solution for low-barrier bibliometric analysis directly from WoSCC spreadsheet exports.

    ● A web-based tool, App4WoSCCinR, was developed for streamlined bibliometric analysis from standard 72- column WoSCC metadata.

    ● The framework produced a summary report and over 100 visualizations across 10 metadata domains, incorporating AAC to quantify dominance.

    ● Analysis of 2,061 SoftwareX articles demonstrated the tool’s practical value for transparent, efficient, and reproducible bibliometric workflows.

    1. Motivation and significance¶

    Bibliometric analysis has become an important approach for evalu ating research productivity, identifying emerging trends, mapping knowledge structures, and assessing scholarly impact across disciplines [1–3]. Widely used tools such as CiteSpace [4], VOSviewer [5], and Bibliometrix [6] enable visualization from standardized Web of Science Core Collection (WoSCC) data [7].However, these tools typically require specific input formats and predefined workflows, limiting flexibility when working with commonly available 72-column Excel-exported WoSCC files.


    Fig. 1. Homepage of App4WoSCCinR illustrating the two-step workflow.

    In practice, such 72-column files often require extensive manual preprocessing—including data cleaning, field standardization, and restructuring—before meaningful analysis can be conducted [8–12]. These steps are time-consuming, error-prone, and hinder reproduc ibility, particularly for users without programming expertise.

    1.1. Existing tools and remaining workflow challenges¶

    A mature software [4–6,13] ecosystem already supports such work with plain text files for non-coders. Reviews of bibliometric software have shown that these tools vary in scope, with different strengths in performance analysis, science mapping, preprocessing, visualization, and user accessibility [14].

    Recent developments have further expanded this ecosystem. For example, BibexPy [15] was introduced as a preprocessing-oriented tool for merging WoSCC and Scopus data, DOI-based deduplication, and metadata enrichment, while BiblioMerge [16] was designed to support merging, duplicate removal, author normalization, and compatibility with downstream bibliometric programs. These developments show that important progress has already been made in automating bibliometric workflows, especially for data integration and cleaning.

    Nonetheless, the availability of multiple tools does not eliminate a practical workflow challenge for many users(i.e., it still requires moving across several steps from exporting records and cleaning metadata to generating publication-ready Figures [17]. Even when robust tools are available, the overall process may remain fragmented for users who prefer a direct upload-and-run workflow on commonly downloaded spreadsheet files rather than multi-stage scripting or tool chaining. A practical need therefore remains for an integrated, accessible workflow that enables bibliometric visualization directly from WoSCC Excel metadata.

    1.2. Practical need for direct and reproducible WoSCC workflows¶

    WoSCC [7] remains one of the most widely used sources for bibliometric research because it indexes journals, conference proceedings, and books across a broad range of disciplines [15,16]. WoSCC records can be exported to spreadsheet formats, which are convenient for users but may still require cleaning, normalization, restructuring, or format conversion before consistent downstream analysis. Related guidance and workflow papers likewise emphasize the importance of combining and cleaning bibliometric data before visualization and interpretation [8].

    This issue is not simply technical; it also affects accessibility and reproducibility. Code-based environments offer high flexibility, but users without programming experience may find preprocessing and multi-tool orchestration burdensome. Conversely, graphical tools may reduce the coding burden but still differ in import expectations, field handling, export options, or output types. Taken together, these workflow-level constraints suggest the value of a low-barrier framework that can accept a standard WoSCC export, perform core preprocessing steps transparently, and generate repro ducible bibliometric outputs within a single environment.

    Additionally, reproducibility remains a major concern in bibliometric research. Many studies lack detailed reporting of data sources, including WoSCC subsets, coverage periods, and search dates, limiting replicability [18]. Furthermore, inconsistencies across databases—such as incomplete author–affiliation links, misclassified document types, and uneven identifier coverage—can introduce bias [19–24] on following visualizations.

    1.3. Study goal and scope¶

    To address this practical need, we developed App4WoSCCinR [25], a browser-based framework designed for users who want to move directly from a WoSCC spreadsheet export to automated bibliometric summaries and visual outputs with minimal manual intervention. In the current implementation, the platform is organized around a simple two-step workflow—data upload and automated execution—and produces both a structured summary report and a large set of exportable visualizations across multiple metadata domains.

    Using articles indexed in WoSCC for SoftwareX as an illustrative case, the present study demonstrates how App4WoSCCinR supports metadata preprocessing, performance analysis, and Figure generation within a unified web workflow. The emphasis is therefore on implementation, usability, and reproducible output generation, while positioning the software as a practical complement to the existing bibliometric tool

    1.4. Contribution of the present work¶

    The contribution of App4WoSCCinR lies in workflow integration and accessibility. Specifically, the framework emphasizes: (1) direct handling of WoSCC spreadsheet exports; (2) minimal manual preprocessing; (3) browser-based execution; (4) automatic generation of structured summary panels and diverse visualization outputs in a single run; (5) and AAC-enhanced dominance [26,27] reporting as a comple mentary layer beyond simple counts and rankings.

    In this sense, the novelty of the software is practical rather than exclusive: it packages several otherwise separate steps into a streamlined web interface intended for transparent and reproducible biblio metric analysis.

    2. Software description¶

    App4WoSCCinR [25] is a web-based bibliometric analysis frame work developed to process standard 72-column WoSCC metadata and generate both structured summary reports and multi-domain visualization outputs within a unified workflow.

    The software is designed to reduce manual preprocessing and to support reproducible bibliometric analysis through a streamlined upload-and-run interface. Beyond the user-facing simplicity of the platform, the system is organized as a modular analytical pipeline that separates data ingestion, metadata normalization, indicator computation, visualization rendering, and export.

    2.1. System architecture and workflow¶

    The architecture of App4WoSCCinR consists of five major modules:

    (1) input parsing,

    (2) metadata cleaning and normalization,

    (3) domain-wise aggregation and indicator computation,

    (4) visualization rendering, and

    (5) export and report generation.

    The overall workflow begins with the upload of a WoSCC spreadsheet file (.xls or .xlsx) or the provision of a valid URL pointing to bibliometric data.

    The imported records are parsed into an internal tabular structure and then passed to preprocessing routines that clean, standardize, and restructure key metadata fields. The normalized outputs are subsequently converted into domain-specific summary tables, which are used to compute bibliometric indicators and generate the final visualizations and summary report. The resulting outputs can then be displayed in the web interface or exported as image and archive files.

    The two-step workflow (Fig. 1) —data upload and automated execution—serves as the entry point to a deeper modular backend that transforms raw WoSCC spreadsheet metadata into publication-ready Figures.

    2.2. Modular design¶

    Five modules are involved in App4WoSCCinR, as shown in Fig. 2.

    2.2.1. Module 1: Input parsing¶

    The input module accepts WoSCC metadata in spreadsheet form and supports both local file upload and URL-based loading. A demonstration dataset is also provided for rapid testing and illustration. Regardless of input source, all datasets are processed through the same parsing logic so that subsequent analytical steps remain consistent.

    The software validates the file format, reads the raw worksheet content, checks that the imported structure is compatible with WoSCC style metadata, and converts the records into a standard internal data frame for downstream processing.

    2.2.2. Module 2: Metadata cleaning and normalization¶

    The second module performs metadata preprocessing, including trimming, delimiter harmonization, missing-value handling, and restructuring of multi-value fields such as authors, affiliations, and keywords. This step is necessary because WoSCC spreadsheet exports, although convenient for users, often require normalization before consistent bibliometric analysis can be performed.

    The preprocessing routines generate structured intermediate tables suitable for domain-level aggregation. For example, author, institution, department, country, and keyword fields are split, standardized, and transformed into countable analysis units. This module therefore acts as the bridge between raw WoSCC metadata and analysis-ready bibliometric objects.

    2.2.3. Module 3: Domain-wise aggregation and indicator computation¶

    After normalization, the third module constructs summary tables across major metadata domains, including 10 metadata doamins. For each domain, the software computes bibliometric indicators such as publication count and h-index, and applies the Absolute Advantage Coefficient (AAC) [26,27] to quantify the relative dominance of leading entities.

    By separating aggregation from preprocessing, the software allows multiple visual outputs to be generated from the same standardized intermediate data rather than repeatedly transforming the original spreadsheet. This design improves consistency, efficiency, and trace ability across outputs.

    2.2.4. Module 4: Visualization rendering¶

    The rendering module converts domain-level summary tables into graphical outputs. In the current implementation, App4WoSCCinR produces more than 100 visualizations spanning multiple metadata domains. These include summary plots[8], slope graphs, chord diagrams [28], Sankey-style relationship displays[29], Slope graphs[30], SSplot [31], world maps, regional maps for China and the United States, and Lotka-related author productivity displays.

    Different metadata structures are routed to different rendering functions. Temporal summaries are used to generate slope plots[30]; relational or co-occurrence data are used in chord and network-based displays; geographic tables are passed to map functions; and clustered data are used to construct SSplots[31]. This modular rendering approach allows the platform to support heterogeneous visualizations within a single analytical environment.

    2.2.5. Module 5: Export and report generation¶

    The final module assembles the outputs into downloadable artifacts.

    A structured summary report is generated to present key contributors and bibliometric indicators across metadata domains, while individual Figs. can be exported as PNG files. In addition, a ZIP package of outputs can be downloaded to support reuse, sharing, and reproducibility.

    This module ensures that App4WoSCCinR functions not only as an exploratory interface but also as a reporting tool capable of producing reusable materials for bibliometric research and presentation.

    2.3. Implementation layers¶

    From an implementation perspective, App4WoSCCinR can be viewed as four interacting layers:

    (1) a front-end Shiny interface,

    (2) a server-side preprocessing layer,

    (3) an analytical engine, and

    (4) a Figure/Report export layer.

    The front-end interface manages file upload, URL input, execution, preview, and downloading. The server-side preprocessing layer handles raw-data parsing and metadata normalization. The analytical engine computes domain-level summaries and bibliometric indicators, including AAC-based dominance [26,27] reporting. The rendering and export layer then transforms these intermediate results into Figures and downloadable reports.

    This layered design clarifies that the two-step user workflow is intentionally simple, whereas the software itself implements a structured backend pipeline for bibliometric data transformation and output generation.

    2.4.3. AAC-based dominance computation¶

    After domain-level counts are generated, App4WoSCCinR appends summary indicators, including the h-index [32] and AAC [8,26,27,33], to identify dominant entities within each bibliometric domain. The following listing illustrates author-level summarization.

    2.5. AAC used to determine dominant strength over the next two elements¶

    The AAC was used to quantify the dominance strength of the leading entity relative to the next two ranked entities. Let $\nu _ { 1 } , \nu _ { 2 } ,$ , and $\nu _ { 3 }$ denote the observed values of the first-, second-, and third-ranked entities, respectively.

    The dominance ratio was calculated as $r = ( \nu _ { 1 } / \nu _ { 2 } ) / ( \nu _ { 2 } / \nu _ { 3 } )$ , and the AAC was then computed as $A A C = r / ( 1 + r )$ . Thus, AAC transforms the dominance ratio into a bounded coefficient between 0 and 1.

    A higher AAC indicates stronger dominance of the leading entity over its nearest competitors, whereas a lower AAC suggests a more even distribution among the top-ranked entities. App4WoSCCinR provides an AAC dashboard to support visual interpretation of dominance patterns across bibliometric domains (Fig. 1) [33].

    2.9.1. R code for visualization and reporting¶

    App4WoSCCinR was implemented on shiny.io[34] to support auto mated bibliometric visualization and reporting from standard 72-col umn WoSCC metadata.

    3.3. Reaching the study goals¶

    This study achieves the study goals that a streamlined web-based framework, implemented through App4WoSCCinR, can effectively (1) perform bibliometric analysis from standard 72-column WoSCC Excel metadata and (2) generate outputs with substantial analytical value.

    As shown in Table 3, the practical contribution of App4WoSCCinR is not to replace established science-mapping tools, but to provide an integrated, low-barrier workflow that accepts standard WoSCC Excel exports directly and generates structured summary reporting plus diverse visual outputs within a single web-based execution environment.

    Through its two-step workflow—data upload and automated analysis—the system produced both a structured performance summary and over 100 visualizations across multiple metadata domains.

    These findings demonstrate that App4WoSCCinR is capable of sup porting bibliometric interpretation in a manner that is clear, efficient, and reproducible. In particular, the integration of the AAC [8,20,21,24, 27] enabled more nuanced identification of dominant entities than simple frequency rankings alone.

    The proposed framework thus meets the study goal of providing a practical and transparent alternative for bibliometric analysis, especially for users seeking low-barrier and reproducible analytical tools.

    4. Impact¶

    App4WoSCCinR extends the earlier 10StepsinExcelforWoS framework [8] into a visualization-oriented bibliometric platform capable of processing standard 72-column WoSCC spreadsheet metadata through a browser-based workflow. By integrating metadata ingestion, preprocessing, structured reporting, AAC-enhanced dominance analysis, and multi-domain visualization within a single environment, the platform reduces manual preprocessing requirements and lowers technical barriers for bibliometric exploration.

    Compared with established tools such as CiteSpace, VOSviewer, and Bibliometrix, the contribution of App4WoSCCinR lies primarily in workflow integration and direct handling of native WoSCC spreadsheet metadata rather than replacement of existing science-mapping software. The framework emphasizes rapid upload-and-run processing together with exportable structured summaries and diverse visualization outputs across countries, institutions, authors, journals, keywords, and temporal trends.

    The inclusion of AAC [8,26,27,36] provides a complementary dominance-oriented indicator that extends conventional frequency-based summaries by quantifying the relative strength of leading entities compared with nearby competitors.

    App4WoSCCinR also improves transparency of bibliometric preprocessing by documenting metadata normalization and structured aggregation workflows. This is particularly relevant because WoSCC metadata may contain inconsistencies such as incomplete affiliations, author-name ambiguity, inconsistent document-type labeling, and incomplete keyword coverage in historical records [40]. Although these issues cannot be fully eliminated by downstream software, deterministic preprocessing and normalization procedures can improve interpretability and reproducibility.

    Several limitations should be addressed. First, the current imple mentation primarily supports WoSCC-derived metadata and does not yet provide direct interoperability with Scopus, Dimensions, or OpenAlex formats. Second, preprocessing outcomes may still be influenced by metadata incompleteness, author-disambiguation ambiguity, and database-specific indexing practices. Third, formal scalability bench marking for very large bibliometric datasets has not yet been systematically evaluated. These limitations remain important directions for future development and validation.

    5. Conclusion¶

    App4WoSCCinR offers a practical web-based framework for analyzing standard 72-column WoSCC metadata through a simple twostep workflow. By generating structured reports, diverse visualizations, and AAC-based dominance indicators without programming, it improves accessibility, transparency, and reproducibility for efficient bibliometric analysis.
